# ラボノート

YouTube運用の日次報告をテンプレートに沿って書く。投稿先はコミュニティで、そのまま貼れる状態にして渡すのがゴール。

テンプレート本体は `assets/template.txt`。**必ずこのファイルを読んで、その構造どおりに出力する。** 見出し、区切り線、空行の入り方、ハッシュタグは変えない。記憶で再現しないこと。

## 書き方

### 材料の集め方

そのセッションで実際に作業していたなら、**まず会話から拾う**。何を作り、何が確定し、何が分かったか。ユーザーに一から聞き直すのは、材料が本当に無いときだけにする。

情報が足りない項目は空欄で出さず、**何が分かれば埋まるかを本文の外で1行聞く**。テンプレートの中に「（要確認）」のような穴を残さない。

### 各項目の性質

| 項目 | 書くもの | よくある間違い |
|---|---|---|
| 今日取り組んだこと | 行為。動詞で終わる | 成果を書いてしまい、次項と重複する |
| 今日のアウトプット | 残った物。数量と名前を入れる | 「作業した」で終わり、何本できたか分からない |
| 数字・気づき | 指標と、そこから分かったこと | **数字が1つも無い**。それなら書き直す |
| 次回やること | 明日の自分が迷わない粒度 | 「頑張る」のような、着手できない粒度 |

「取り組んだこと」と「アウトプット」は必ず別物にする。**台本を書いた**（行為）と**台本3本**（成果）は、同じことの言い換えではない。

### 数字が無い日

指標を見ていない日は、その事実自体を書く。「今日は制作のみで数値確認なし」と書けば、後から読んだとき何をした日か分かる。無理に数字をひねり出すより正確。

### 任意セクション

区切り線から下は、**書くことが無ければ丸ごと省く**。見出しだけ残して中身が空だと、読む側は「困っていないのか、書き忘れたのか」を判別できない。

**仮説**は検証できる粒度にする。「動画の質を改善すると再生数が向上する」は何も言っていない。「冒頭5秒でセリフを出すと、視聴維持率が向上する」なら、次の動画で確かめられる。

**達成度**は5段階から1つ選び、`★★★☆☆` のように塗りつぶした形で出す。`★☆☆☆☆〜★★★★★` の表記をそのまま残さない。

## 出力

装飾を足さない。見出しをMarkdownにしたり、箇条書きの `・` を `-` に変えたりしない。コミュニティに貼る素のテキストとして出す。

前置きも要らない。「以下がラボノートです」と書かずに、本文から始める。ユーザーへの補足（聞きたいこと、判断が要る点）は、**本文をコードブロックで囲んだ後に**書く。貼り付け時に混ざらないようにするため。
