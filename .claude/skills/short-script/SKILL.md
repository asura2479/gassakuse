# ショート動画 台本作成

アニメ解説系ショートの台本を書くためのスキル。狙いは「最後まで見られる1本」を再現性のある手順で作ること。

書き始める前に必ず `references/channel.md` を読む。チャンネルの固定条件（尺・話者・視聴者層・表現の線引き）がそこにあり、これを外すと台本は作り直しになる。

## 手順

### 1. ネタ被りを潰す

投稿管理表（`references/channel.md` にID）を読み、**同じ切り口が既にあるか**を確認する。ここを飛ばすと、既出テーマを別の言い回しで作り直すだけになり、伸びない。

見るのはタイトル文字列の一致ではなく**切り口**。「ロキシー教の理由」が既出なら、「ロキシーが崇拝される話」は角度を変えても被りと判断する。逆に、同じキャラでも扱う感情が違えば別ネタとして成立する（例：エリスの暴力ネタ ≠ エリスが去った理由）。

未使用のキャラ・事件を洗い出してから題材を決めると、選定が速い。

### 2. アニメの放送範囲を調べ直す

`references/channel.md` の放送状況表は**古くなる前提**で書いてある。着手時に必ずWebで確認し、ずれていたら表を直す。

ここを怠ると事故る。「原作限定だから伸びる」と思って書いた内容が先週アニメで放送済み、という失敗が一番痛い。放送中の作品なら、直近の話数が原作の何巻あたりかまで押さえる。

**調査経路**: `WebSearch` は使える。ただし `youtube.com` `x.com` `ncode.syosetu.com` など多くのサイトは egress proxy にブロックされていて `WebFetch` が通らない。検索結果のスニペットで組み立てるか、通るドメインを探す。

**原作のファイルがあるなら、それを最優先で読む。** EPUBは実体がzipなので、展開してタグを剥がせば全文検索できる。目次から章立てを取り、キャラ名の出現回数を巻ごと章ごとに数えると、そのネタがどこにあるか一発で絞れる。

```
unzip -oq book.epub -d out/           # 展開
# xhtml からタグを除去して1巻1テキストに落とし、章見出しで分割、
# キャラ名の出現数で密度マップを作ると当たりの章がすぐ見つかる
```

一次資料が使えるときにまとめブログで済ませるのは、単に精度が落ちる。原作にあたって初めて「誰が問題を解決したのか」「そのキャラは生きているのか」が確定する、という場面が実際に起きる。

**一次資料がない場合、裏取りは必ず複数ソースで。** まとめブログは相互にコピーし合っていて、誤情報がそのまま増殖している。1つのブログにしか書かれていない設定は、台本に断定形で書かない。実際、キャラの生死のような重要な点で情報源が食い違うことがある。

### 3. 競合を構造で読む

競合動画（文字起こしでよい）がある場合は `references/analysis.md` のチェックリストで分解する。

抽出するのは**構成・テンポ・感情設計・引っ張り方**だけ。セリフ、言い回し、固有のキャッチフレーズ（「〇〇がバグってる」のような署名的表現）は持ち込まない。同じ機能を別の語彙で作り直す — これが「参考にする」と「パクる」の境界になる。

### 4. 型に流し込む

`references/format.md` の「ラベル → 証明 → 未完了」型と尺配分表に沿って本文を書く。型は骨格であって拘束具ではないので、題材が要求するなら配分は動かしてよい。ただし**冒頭3秒と末尾の未完了エンドだけは崩さない**。ここが視聴維持率を決めている。

完成形が見たいときは `references/example.md` を読む。型がどう埋まり、どこで解釈が入っているかを1本通しで示してある。

### 5. 尺を数える

書き終えたら文字数を数え、`references/format.md` の換算式で秒数を確認する。TikTokの収益条件があるため、**60秒を割ったら不合格**。足りなければ第2エピソードを伸ばす（フックや説明を膨らませるとテンポが死ぬ）。

### 6. 出力する

以下を毎回そろえて出す。台本だけ出しても制作に入れない。

1. タイトル案（5〜6本、推し1本を明示）
2. 冒頭フック案（3〜5本、推し1本を明示）
3. 台本本文（秒数見出し付き・改行多め）
4. 構造対応表（どのブロックがどの役割か）
5. 貼り付け用CSV（`話者,テキスト` の1行1セリフ形式）
6. 事実確認が必要な箇所（原作設定に踏み込んだ部分）

## 事実の扱い

解説チャンネルなので、原作設定の誤りは信頼を直接削る。**確信が持てない設定は台本に断定形で書かない。** 書くなら、出力の最後に「ここは要確認」と明示して、ユーザーが潰せるようにする。

特に危ないのは、因果の逆転（「Aのために B を選んだ」と書いたが、実際は B は偶然だった、など）。キャラの動機を語るときは、それが原作の記述なのか自分の解釈なのかを区別すること。解釈なら解釈と分かる書き方にする。

## やりがちな失敗

- **冒頭に情報を詰める** — 作品名・キャラ名・状況を3秒以内に言おうとすると必ず滑る。冒頭は感情と疑問だけでいい。名乗りは4秒目以降。
- **オチた直後に終わる** — 最大の離脱点はオチの瞬間。そこで動画が終わると「見終わった感」が出て、最後まで見た扱いにならない。必ず第2エピソードか未完了エンドを被せる。
- **1文が長い** — 20文字を超えると音声で聞き取れなくなり、字幕も2行に折れる。切る。
- **説明で埋める** — 解説チャンネルの癖で背景説明が伸びる。説明は「オチの理解に必要な最小限」まで削る。
- **結論を先に言う** — 「〜だったんです」を中盤で出すと、そこで離脱する。結論は引っ張る。
